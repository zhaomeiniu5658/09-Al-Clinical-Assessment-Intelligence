# 部署说明

## 架构

本机运行两套独立服务：

- Dify `1.16.1`：位于 `D:\Project\dify`，提供大模型工作流能力。
- 临床评估质控系统：位于 `D:\Project\09-Al-Clinical-Assessment-Intelligence`，使用 Docker MySQL 作为业务数据库。

音频转录与 AI 质控由 FastAPI 的后台任务执行：上传或重试接口会立即返回，前端通过任务状态刷新查看处理进度。

## 前置条件

- Docker Desktop 已启动，并处于 Linux Containers 模式。
- 本机端口 `80`、`443` 由 Dify 使用。
- 质控系统 Docker 前端使用 `8080`，开发服务器使用 `5173`，后端 API 使用 `8000`。

## Dify

### 启动与停止

```powershell
Set-Location D:\Project\dify
docker compose up -d
docker compose ps
```

访问 [http://localhost](http://localhost)，首次访问时按页面提示创建 Dify 管理员账号。

停止服务：

```powershell
Set-Location D:\Project\dify
docker compose down
```

查看日志：

```powershell
Set-Location D:\Project\dify
docker compose logs -f api web worker nginx
```

## 质控系统

### 配置环境变量

首次部署时创建本地配置：

```powershell
Set-Location D:\Project\09-Al-Clinical-Assessment-Intelligence
Copy-Item .env.example .env
```

修改 `.env` 中的以下值：

- `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`
- `JWT_SECRET_KEY`：使用随机长字符串
- `DIFY_OPENAI_BASE_URL`、`DIFY_HAMD_API_KEY`、`DIFY_HAMA_API_KEY`、`DIFY_PHQ9_API_KEY`
- `FRONTEND_PORT=8080`：避免与 Dify 的 `80` 端口冲突

讯飞 APPID、APISecret、APIKey、WebAPI 地址和个性化热词通过系统登录后的“系统设置”页面管理，不需要写入 `.env`。

### 启动

```powershell
Set-Location D:\Project\09-Al-Clinical-Assessment-Intelligence
docker compose up -d --build
docker compose ps
```

访问地址：

- 质控系统前端：[http://localhost:8080](http://localhost:8080)
- 后端健康检查：[http://localhost:8000/health](http://localhost:8000/health)
- 后端 OpenAPI：[http://localhost:8000/docs](http://localhost:8000/docs)

### Docker MySQL

Docker Compose 中的 `mysql` 服务是唯一的业务数据库：

- 容器内地址：`mysql:3306`
- 宿主机地址：`localhost:3306`
- 项目内数据库目录：`D:\Project\09-Al-Clinical-Assessment-Intelligence\data\mysql`
- 项目内上传文件目录：`D:\Project\09-Al-Clinical-Assessment-Intelligence\data\storage`

后端启动时自动运行 `alembic upgrade head`，无需手动执行迁移。不要同时启动另一套占用 `3306` 端口的 MySQL 服务。

Compose 使用项目内绑定目录，不再使用 Docker 全局命名卷。`.env`、`data/mysql` 和 `data/storage` 都属于项目运行环境，迁移时需要一起备份和复制。

### 从旧 Docker 命名卷迁移

如果此前版本已经启动过并使用 `mysql_data`、`app_storage` 命名卷，先启动 Docker Desktop，再在项目目录执行迁移脚本。脚本会检查目标目录为空，停止项目容器并复制数据；旧命名卷会保留，不会删除。

```powershell
Set-Location D:\Project\09-Al-Clinical-Assessment-Intelligence
.\scripts\migrate-docker-volumes.ps1
docker compose up -d --build
docker compose ps
```

如果自动识别不到旧卷，可先查看实际名称：

```powershell
docker volume ls
```

然后显式传入卷名：

```powershell
.\scripts\migrate-docker-volumes.ps1 -MySqlVolume "旧的MySQL卷名" -StorageVolume "旧的文件卷名"
```

确认系统数据正常后，继续保留旧卷一段时间作为回退备份。不要执行 `docker compose down -v`，也不要删除 `data/mysql` 或 `data/storage`。

### 本地前端开发

```powershell
Set-Location D:\Project\09-Al-Clinical-Assessment-Intelligence\frontend
npm ci
npm run dev
```

开发地址为 [http://localhost:5173](http://localhost:5173)。Vite 会将 `/api` 请求代理到 `http://localhost:8000`。

### 日常运维

```powershell
Set-Location D:\Project\09-Al-Clinical-Assessment-Intelligence
docker compose logs -f backend mysql
docker compose restart backend
docker compose down
```

`docker compose down` 不会删除项目目录下的数据库文件或上传文件。日常不要执行 `docker compose down -v`，也不要直接删除 `data` 目录；清理前应先做完整备份并由管理员确认。

### 迁移到另一台电脑

1. 执行 `docker compose down` 停止服务。
2. 复制整个 `D:\Project\09-Al-Clinical-Assessment-Intelligence` 文件夹到新电脑，至少保留 `.env`、`docker-compose.yml` 和 `data` 目录。
3. 新电脑安装并启动 Docker Desktop，使用 Linux Containers 模式。
4. 在项目目录执行 `docker compose up -d --build`。
5. 执行 `docker compose ps`，再访问 `http://localhost:8080`。

不需要导出或恢复 Docker 命名卷。`.env`、`data/mysql` 和 `data/storage` 含有敏感配置及业务数据，不要提交 Git 或发送给无权限人员。

## 讯飞转录设置

登录质控系统后，进入“系统设置”。可配置：

- 模型名称：非实时语音转写大模型
- APPID
- APISecret
- APIKey
- WebAPI：`https://office-api-ist-dx.iflyaisol.com`
- 个性化热词：每行一个词

APISecret 和 APIKey 只接受写入，不会从服务端返回明文。保存后，新提交的音频任务将使用该配置。

## 知识库对外 API

管理员登录后进入“知识库”，通过“分类设置”维护资料分类，再通过“对外 API”开通接口并复制生成的 API Key。密钥只在生成或重新生成时显示一次；关闭接口会立即撤销当前密钥。

对接方在请求头中携带：

```text
X-Knowledge-API-Key: kb_your_api_key
```

可调用的接口：

- `GET /api/v1/external/knowledge`：分页检索知识条目，支持 `page`、`page_size`、`keyword`、`category` 参数。
- `GET /api/v1/external/knowledge/{entry_id}`：获取单条知识详情。
- `GET /api/v1/external/knowledge/{entry_id}/attachment`：下载条目附件。
- `GET /api/v1/external/knowledge/categories`：读取资料分类。

本机调用示例：

```powershell
curl.exe http://localhost:8000/api/v1/external/knowledge -H "X-Knowledge-API-Key: kb_your_api_key"
```
