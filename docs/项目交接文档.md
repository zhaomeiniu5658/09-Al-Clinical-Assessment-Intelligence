# 项目交接文档

## 1. 项目概览

本项目是一个“AI 临床评估质控平台”，用于上传录音、调用讯飞非实时语音转写大模型做转录，再结合质控规则和后台任务生成分析结果。系统同时包含用户管理、知识库、系统设置、工作台等后台功能。

当前项目已调整为：

- 前后端分离
- Docker Compose 部署
- 数据库使用 Docker MySQL
- 任务异步执行，不让用户等待转录和分析完成
- 不再使用 Redis / Celery

## 2. 技术栈

- 前端：Vue 3、TypeScript、Vite、Element Plus、Pinia、Vue Router
- 后端：FastAPI、SQLAlchemy、Alembic
- 数据库：MySQL 8.4（Docker）
- 部署：Docker Compose
- 音频转录：讯飞非实时语音转写大模型
- 文件处理：后端容器内已安装 `ffmpeg`

## 7. 任务处理方式

项目中的音频识别和质控分析采用后台异步任务执行：

1. 用户上传文件并创建任务
2. 接口立即返回
3. 后台开始讯飞转录
4. 转录完成后进入质控分析
5. 分析完成后更新任务状态
6. 前端通过列表状态查看结果

这个设计的目的，是避免用户在前台一直等待接口响应。

## 15. MP4 无法解析的问题

项目已处理 MP4 上传场景：

- 后端容器中安装了 `ffmpeg`
- 上传 MP4 后先提取音频
- 再转给讯飞转写接口

如果再次出现解析失败，通常先看：

- 文件是否损坏
- 容器内 `ffmpeg` 是否正常
- 讯飞接口参数是否正确

容器内检查 `ffmpeg`：

```powershell
docker compose exec backend ffmpeg -version
```

## 17. 常见问题排查

### 17.1 其他电脑打不开页面

优先确认：

- 访问的是 `http://本机局域网IP:8080`
- 不是 `http://localhost:8080`
- 当前电脑 IP 没有变化
- 防火墙放行了 `8080`
- Docker 前端容器正在运行

### 17.2 后端健康检查打不开

健康检查不是业务页面，只返回 JSON。

正确地址：

```text
http://localhost:8000/health
```

其他电脑访问：

```text
http://本机局域网IP:8000/health
```

### 17.3 新建用户无法登录

排查顺序：

1. 用户是否启用
2. 密码是否已通过“修改密码”更新
3. 是否使用了管理员创建的真实账号
4. 浏览器是否还保留了旧登录状态
5. 后端日志是否有认证失败信息

### 17.4 记住密码重启后无效

现在的实现是记住登录状态，不保存明文密码。

如果仍然无效，排查：

- 登录时是否勾选了“记住密码”
- 浏览器是否禁止本地存储
- 是否清理过浏览器站点数据
- JWT 过期时间是否被改短
- 前端路由守卫是否能正常调用 `/api/v1/auth/me`

### 17.5 任务长时间分析中

排查：

- 系统设置中的讯飞参数是否完整
- 讯飞接口是否可用
- 上传文件是否过大或编码异常
- 后端日志是否有 ASR 或 AI 质控异常
- 如果使用 Dify，Dify 服务和 API Key 是否正常
